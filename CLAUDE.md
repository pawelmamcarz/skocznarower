# CLAUDE.md

This is the long-form architecture guide for coding agents (Claude Code, Grok, Codex). Keep `AGENTS.md` as the short operational checklist. Put duplicated sources of truth and gotchas here.

## What this is

Marketing site + bookings app for **skocznarower.pl**, a bicycle service shop in Grodzisk Mazowiecki (PL). Content is Polish. Deployed as a single Cloudflare Worker with the static-assets binding; the Worker handles the apex → www redirect, the booking API, the `/admin` panel, a five-minute notification-outbox cron, and daily maintenance/reminder jobs. Static HTML/images fall through to the assets binding.

## Architecture

### Pages (static HTML at the repo root)
- `index.html` — main marketing page. CSS and JS are inlined; do not split into separate files unless asked. Section anchors: `#o-mnie`, `#uslugi`, `#cennik`, `#faq`, `#kontakt`.
- `umow.html` — booking flow, served at `/umow`. Calls `GET /api/availability?date=` then `POST /api/bookings`.
- `index.html` also calls `GET /api/next-slot` to show a "najbliższy wolny termin" nudge pill in the hero (reuses `SCHEDULE`/booking/`blocked_slots`; scans ~21 days, skips today's past hours). **The pill is never hidden** (changed 2026-08-29): it ships rendered with a static fallback ("Codziennie 16:00 do 19:00, tylko po umówieniu") inside `#next-slot-text`, and the script only swaps that text for the live term, so an API error or a full calendar leaves the opening hours on screen instead of removing the element. Keep the `.next-slot[hidden]{display:none}` rule anyway (it backs the attribute if the pill is ever conditionally hidden again). When the API returns `{date, time}`, the pill links to `/umow?date=YYYY-MM-DD&slot=HH:MM` and `umow.html` reads those query params to preselect the date and slot (format-validated, slot only if still free).
- **Hero hierarchy (2026-08-29 UX pass, all three languages)**: eyebrow carries the street (`Grodzisk Mazowiecki · Jesionowa 18`), `.hero-sub` states the concrete offer (scope, `od 150 zł`, typical turnaround), then the pill, then `.hero-foot` with exactly **one** green `.btn-green` plus phone and WhatsApp as secondary `.hero-link` text links. The old `.hero-spec`/`.hero-divider` pair is gone. `.hero` is `min-height: max(620px, 100svh)` with no fixed height, so the taller content grows the section instead of sliding under the fixed nav; below 820px the whole `.hero-foot` is hidden and the fixed `.mobile-bar` carries the three actions.
- **`#uslugi` hierarchy (2026-08-29)**: three `.service-card` specialisation cards (Dirt Jump, BMX, Zaplatanie kół, copy and icons unchanged) sit above a compact `.services-list` of the remaining six rows, renumbered 01-06. Every card and row ends with a `.service-go` link into `/umow?service=<id>`; the ids must exist in `SERVICES`, so a renamed id breaks the deep link silently. Dirt Jump and BMX link to bare `/umow` on purpose: they are bike types, not `SERVICES` entries.
- **`?service=` prefill**: `umow.html` (and both mirrors) read `?service=<id>` in `prefillFromQuery`, whitelist it against their own `SERVICES` copy, tick the radio and fire a bubbling `change` so the summary updates. It runs **before** the `?date=` validation, so a service without a date still preselects. Values stay Polish ids in every language. The lookup must query the **form**, not `#services`: ten of the fourteen radios live in the collapsed `#services-rest` group (below), and a `#services`-scoped selector silently fails for them.
- **Step 01 split (2026-08-29)**: the four services flagged `common: true` in each page's own `SERVICES` copy (przegląd podstawowy, przegląd kompleksowy, regulacja, wymiana części) render in `#services`; the other ten render in `#services-rest`, hidden behind the `#services-more` button. `common` is a display-only flag, it does not exist in `src/index.js` and does not affect the id/price sync rule. All fourteen radios are in the DOM from the start, so validation, `collectValues` and the prefill work whether or not the group is expanded; `setServicesRest(true)` opens it when the prefilled service lives there. Prices were always shown per option (`.choice-price`), that part never needed fixing.
- **Mobile summary bar**: below 600px `.summary` becomes a fixed bar at the bottom of the viewport, so the running choice stays visible through all four steps instead of appearing only above the submit button; `#booking-form` carries a matching `padding-bottom` so the bar never covers the submit.
- **FAQ (2026-08-29)**: the first four questions (jak umówić, ile trwa, dirt/BMX, e-bike) render open; questions 5-12 carry `data-faq-extra hidden` and a `.faq-more-toggle` button reveals them. All twelve stay in the DOM and in the `FAQPage` JSON-LD, so nothing is lost for search. `.faq-list` now carries the top border and each `.faq-item` its own bottom border, so the list closes correctly whatever number is visible.
- **Section order (2026-08-29)**: the dirt minigame (`.dirt-section`) and the sticker section (`.section-tilt`) moved **below** `#kontakt`; entertainment must not sit between the cennik and the contact details. Page order is hero, `.trust`, `#o-mnie`, `#uslugi`, `#opinie`, `#cennik`, `#faq`, `#przypomnienie`, social, `#kontakt`, minigame, sticker, footer.

The finished PDFs and their `.source.html` files are all excluded by `.assetsignore`; public pages must not link them or imply that workshops, passes or vouchers can be bought. If the offer is approved later, update the source content, render and visually verify both PDFs, then remove only the finished files from `.assetsignore` in the same change.
- `gra.html` + `en/gra.html` + `ua/gra.html` - the browser game **Skoczna Rider**, served at `/gra` (`VideoGame` JSON-LD root + `BreadcrumbList` + `FAQPage`). It is entertainment, not a bookable service: deliberately **not** in `SERVICES`, not in the cennik, and never presented as something the shop sells. The engine is the shared `game.js` (second sanctioned shared script after `turnstile.js`); each page inlines its own CSS with the canonical token block and declares translated copy in `window.GAME_I18N`, while the Polish strings are the engine defaults, so a PL copy change means editing `game.js`, not the page. Game data lives in `game.js`: `BIKES` (bmx, dirt, gravel, kolarka; cost and handling stats) and `LEVELS` (eight tracks, each its own procedural terrain seed and scenery palette). Level order is the unlock chain: finishing level N unlocks N+1, so reordering `LEVELS` reorders progression. Coins are earned per run and buy bikes, carrots are the fuel pickups. The visible control labels are **Korba**, **Hamulec** and **Pompuj** (never "Gaz"), matching the homepage minigame buttons. `Pompuj` (`.g-pump`, keyboard space / ArrowUp / W) queues one hop per press: it only fires with both wheels down, leaves the bike level, and on a downslope converts the drop into speed. Two invariants behind it: the `pumptrack` level runs with `kickers: 0` (rollers only, it is the track for learning to pump), and the window keydown handler must keep bailing out on form controls and on `run.preview`, otherwise the ranking form cannot be typed into and the page stops scrolling with space.
- **PWA**: `gra.webmanifest` (plus `en/` and `ua/` copies with their own `start_url`/`id`) and `game-sw.js` make the game installable on Android and iOS. The service worker sits at the repo root so its scope covers `/gra`, but it only answers requests for the game pages and the listed game assets and otherwise never calls `respondWith`, so `/api/*`, `/admin*` and the rest of the site keep going straight to the network. Bump `CACHE` in `game-sw.js` whenever `game.js` or the game pages change, not only when the asset list does: without a bump the previously installed worker keeps serving the cached engine under the new copy. `/game.js` is network-first (cache only as the offline fallback) for the same reason.
- **Game API + player base**: `POST /api/game/register` sends a six-digit SMS code (stored only as an HMAC in `game_verifications`), `POST /api/game/verify` creates the row in `game_players` and returns a signed player token, `POST /api/game/score` records a run in `game_scores`, and `GET /api/game/leaderboard?level=` returns the top ten nicks. Consent is split: `consent_data` is required for the ranking, `consent_marketing` is optional, and only the second one may feed commercial SMS. Cost guards: the shared `PUBLIC_POST_LIMITS` entries, a 60 s resend gap and 4 codes per number per day, plus a global `GAME_SMS_DAILY_BUDGET` (150 codes per 24 h) counted in `request_rate_limits`. The owner reads the base at `/admin/gracze` (list + `?zgoda=marketing` filter + `?format=csv` export). Without `SESSION_SECRET`/`ADMIN_PASSWORD` the whole namespace answers 503, and without `SMSAPI_TOKEN` registration returns 502 instead of silently pretending to send.
- `uploads/` holds every image referenced by the pages. New images go here and are served at `/uploads/<name>`.
- **Cennik entry point**: `#cennik` opens with `.price-lead` (the "ceny za robociznę, części osobno" note, moved up from the last `.price-cat` so it is read before the prices) and three `.price-anchor` cards linking to `/umow?service=<id>` (szybka naprawa od 35 zł, przegląd podstawowy od 150 zł with the `.price-anchor-hi` highlight, przegląd kompleksowy od 340 zł). Their prices are part of the price-sync surface list above: change a price and these cards change too.
- `sitemap.xml` + `robots.txt` are static. The sitemap lists every public page above — when adding/removing a page or meaningfully changing content, update it and bump `<lastmod>`.
- `llms.txt` + `llms-full.txt` are static AI/LLM index files served as-is. `llms.txt` is the short index (intro blurb with a service/price summary, e.g. bleeding od 100 zł, plus a linked list of the main pages) and points at `llms-full.txt`, the self-contained long-form copy (full service list, cennik, FAQ, contact). Keep both in sync when services, prices, hours, or pages change.
- **i18n mirrors (added 2026-07-13)**: `en/` and `ua/` hold translated mirrors under the **same filenames**, served extensionless by the ASSETS binding (`/en/umow` → `en/umow.html`; no Worker routing needed). Rules that keep the mirrors honest: (1) **any content change on a PL page must be mirrored in both translations**, prices/hours/phone included; (2) form `value`s/ids posted to the APIs stay Polish, only labels are translated; (3) every page in a cluster carries the same `pl`/`en`/`uk`/`x-default` hreflang set; the Ukrainian URL prefix is `/ua/`, while language metadata remains `uk`/`uk_UA`; (4) internal links inside a mirror stay within its language prefix; (5) notifications remain Polish. The public set currently contains 36 sitemap URLs, including the pumptrack guide, wheel-building, e-bike service landings, the game `/gra`, and the resistance calculator in all languages.


### Audit fixes (2026-09-04)
- Public pages now include `prywatnosc.html` in PL/EN/UA (36 sitemap URLs total). The three `404.html` pages are noindex and are served with HTTP 404 by the Worker fallback. Every page has a main landmark, skip link and privacy footer link.
- `pickup_requested` and `pickup_address` travel with a booking (migration 0022). Transport can accompany a repair; the legacy `odbior` service still implies pickup. The address is mandatory for new pickup requests. UI summaries, admin views, SMS/email and calendar distinguish pickup from a workshop visit; repair and transport prices remain separate.
- Public availability, booking and next-slot use the same Warsaw-time rules and a 60-day horizon. Same-day future slots are allowed. Admin lifecycle updates use atomic status conditions and `expected_status` to reject stale forms.
- Workshop forms carry a stable UUID `idempotency_key` across retries of the same payload. Migration 0022 stores the key/hash; repeated identical submissions return the first result. Public failures include a stable `code` for translated messages.
- Turnstile form handlers set `form.dataset.submitting = 'true'` after validation and before the first await, then delete it in finally. They restore disabled state from `form.dataset.turnstileReady`. The shared helper only resets a token after a real submission; invalid fields and challenge callbacks cannot bypass submission guards.
- First-entry attribution is captured in sessionStorage under `skoczna-attribution-v1` on public pages, then read through a bounded allowlist by booking/workshop forms. Language values are pl/en/uk, with legacy ua accepted by the backend. This does not activate Google Analytics or Meta Pixel.
- Workshops show a concise planned programme and a free interest list. There are no public package/voucher prices, sales or AI demonstration videos. Venue availability and start dates remain unconfirmed.
- `/api/game/run` issues a signed, player/level/bike-bound single-use run ticket (migration 0023). The client obtains it before starting physics and submits `run_token`, `duration_ms`, `finished` with the score. Expiry, elapsed time, score arithmetic and per-track plausibility are validated. This limits obvious fabrication/replay; it is not authoritative server-side physics. Failed/offline submissions are labelled as browser-only records. Cache version is `skoczna-rider-v3`.
- **Calculator model (2026-09-04 replacement):** `globalThis.Bieznik` / `window.Bieznik` exposes frozen `DEFAULTS`, `LIMITS` and `compute(input)`. Defaults: `{mass:90,speed:25,grade:0,wind:0,cda:0.4,crr:0.006,efficiency:0.97,airDensity:1.225}`. Mass is the complete rider+bike+luggage mass in kg; speed and wind are km/h; grade is percent rise/horizontal run. Positive wind is headwind, negative is tailwind. CdA is m², Crr and efficiency are dimensionless, air density is kg/m³. Missing fields use defaults; supplied values must be finite numbers inside the exported limits, otherwise `RangeError` is thrown (no string coercion).
- **Calculator output and signs:** `compute` returns `{rolling,aero,gravity,netWheel,pedaling,braking,drivetrain}`, all in watts. With ground speed `v`, relative air speed `u = v + wind/3.6`, and `theta = atan(grade/100)`, aerodynamic power is `0.5*rho*CdA*u*abs(u)*v`, rolling power is `Crr*m*g*cos(theta)*v`, and gravitational power is `m*g*sin(theta)*v`. Sum these signed terms before separating pedaling (`max(0,netWheel)/efficiency`) and braking (`max(0,-netWheel)`). Drivetrain losses apply only when pedaling. At zero speed every mechanical-power term is zero. Never use relative air speed cubed in wind, discard downhill gravity, or add braking power to pedaling demand.
- **Calculator scope:** this is a reduced model based on Martin et al. (1998), https://doi.org/10.1123/jab.14.3.276, not a measured fit to the visitor’s bicycle. CdA/Crr and air density are stated assumptions. There is no acceleration, crosswind, individual wheel-bearing term, pressure prescription, fitness estimate, training forecast, upgrade price list or route-average calculation. A faster-than-bike tailwind uses the signed one-dimensional drag approximation with the same CdA for airflow from either direction. Inputs and calculations stay in the browser; no route upload or weather request remains. Keep public descriptions and privacy copy aligned with this scope.
- **Calculator validation:** `tests/calculator.test.js` imports the browser IIFE and tests independent numerical cases, wind direction, uphill/downhill balance, zero speed, steady-speed mass and velocity scaling, and input limits. Run `npm test -- tests/calculator.test.js` for this model; `npm test` includes it alongside the Worker/D1 suite. Browser QA should also check PL/EN/UA, input/result updates, validation and layout at mobile and desktop widths.

### Design tokens (inline CSS across public pages)
There is no shared stylesheet: every public HTML page inlines its own `<style>` with a `:root` token block, so new landing pages and all PL/EN/UA mirrors must copy the canonical tokens. The core palette/fonts (`--bg`/`--bg2`/`--bg3`, `--accent` `#9fe22e`, `--accent-dim`, `--white`, `--border`, `--fd` Bebas Neue, `--fb` DM Sans) are mirrored across the site. Three tokens were unified after drifting apart and are now the canonical values everywhere:
- `--radius: 2px` — corner radius for the button family (`.btn`/`.btn-green`/`.nav-cta`/`.btn-submit`/`.reminder-input`/`.map-wrap`). Previously `2/4/6/8px` across files; the homepage's sharp `2px` is the brand canon.
- `--accent-hi: #b5f040` — the brighter green used on `:hover` of accent surfaces. Previously a mix of `#b5f040` (index) and `#b6f23d` (subpages).
- `--muted: #969696` — secondary/label text, chosen to pass WCAG AA (≥4.5:1) on the darkest background it sits on (`--bg3 #1c1c1c`). Previously `#777` (index, failed AA) vs `#888` (subpages).
When changing a button radius, the hover green, or muted text, edit the **token** in every affected page and all language mirrors; do not hardcode a hex or reintroduce raw `#b5f040`/`#b6f23d`/`#777`/`#888`. The token set is deliberately thin: spacing, shadow, and font-size stay as raw magic numbers, not tokens.

Two `index.html`-only mechanics tied to the above: (1) the homepage nav is transparent and `position:fixed` over the hero, offset down by `var(--banner-h, 0)`; nothing sets `--banner-h` since the vacation banner's removal (2026-07-10), so it resolves to 0, but the hook stays for any future top banner (see the vacation banner pattern above); `.nav.stuck` resets it to `top:0` once scrolled. (2) Every public page needs a `.nav-toggle` hamburger that toggles `.nav-links.open`, with matching Escape/click-to-close JS. The homepage collapses at 820px and subpages generally at 720px (the homepage had an extra 980px early-collapse rule while `Gra` sat in the menu; removed 2026-08-29 with the menu itself). **`Więcej` dropdown** (2026-08-29): `Gra` and `Kalkulator` left the flat menu on all 36 public pages and now sit in a `<li class="nav-more">` dropdown (`#nav-more-btn` toggles `#nav-more-menu`, Escape and outside-click close it), plus a `<p class="footer-links">` row in every footer. The homepage menu is O mnie / Usługi / Cennik / FAQ / Kontakt / Więcej plus the language switch and the CTA; subpages keep Usługi / Cennik / Kontakt / Więcej. Two things make it work across pages that each inline their own CSS: the button is appended to the page's own `.nav-links a` selector so it inherits that page's nav typography (12px muted on the homepage, 14px white on subpages), and the mobile block is emitted at **that page's** nav breakpoint (820px homepage, 720px elsewhere), where `.nav-more-btn` is hidden and `.nav-more-menu` is forced back to `display: block; position: static` so both entries show inline in the hamburger menu. That last rule deliberately beats the `hidden` attribute; do not "fix" it by removing `hidden` from the markup, desktop needs it. The `lang-sw` entry on `gra.html` and `kalkulator.html` still points at `/en/gra`, `/ua/kalkulator` and so on: those are language switches, not nav items, and must stay. The fixed `.mobile-bar` CTA is mobile-only via the `@media(max-width:820px)` rule (`display:none` otherwise), so never give it an inline `display:flex` (it leaks onto desktop and covers the hero pill + footer).

### Worker (`src/index.js`)
- Routed to both `skocznarower.pl/*` and `www.skocznarower.pl/*`. Apex requests get a 301 to `www`. Both routes must stay: drop `skocznarower.pl/*` and apex requests never reach the Worker (the 301 never fires); drop `www.skocznarower.pl/*` and `www` traffic stops being handled.
- `wrangler.jsonc` sets `assets.run_worker_first: true`, so the Worker sees every request first. `/api/*`, `/admin*`, `/r`, and `/warsztaty/potwierdz` are handled in the Worker; everything else falls through to a plain `env.ASSETS.fetch(request)` passthrough. On `GET /` (and `/index.html`) the Worker then runs `injectReviewsSSR` over that asset response. The extensionless resolution (e.g. `/umow` → `umow.html`) is done by the Cloudflare ASSETS binding itself, not by code in `src/index.js`, so do not go hunting for that routing logic in the Worker.
- Turnstile (optional bot protection): `turnstile.js` is the one shared public script (not inlined). Forms call `GET /api/security-config` for the site key; protection is live only when both `TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY` are set. Tests expect the script on all nine public forms (PL/EN/UA × booking, workshop, reminder).
- **Sources of truth that mirror the UI** live as constants at the top of `src/index.js`:
  - `SERVICES` — service list and price labels (14 entries; this is the bookable-form whitelist). Gotcha: `umow.html` carries its **own** copy of `SERVICES` (and `BIKE_TYPES`) as JS arrays near the top of its `<script>`, rendered as a radio-group (`#services`, `renderChoices`), **not** a `<select>`. So editing `SERVICES` in `src/index.js` alone does **not** update the form; ids and prices must match across both, while `umow.html` deliberately uses shortened display labels (e.g. `Odbiór i odwóz roweru` vs `...(adres podaj w notatce)`, `Wymiana części` vs `...(klocki, linki, dętka...)`, `Inne (opisz niżej)` vs `Inne (opisz w notatce)`). Also keep in sync: the visible cennik in `index.html` (`.price-row` sekcja; a finer-grained breakdown of ~26 line items, so the `SERVICES` names appear inside it but the cennik adds sub-items), **i** dodatkowe powierzchnie marketingowe: `serwis-rowerow-pruszkow.html` (Service+OfferCatalog JSON-LD + visible cennik list + FAQPage answer + visible FAQ), `serwis-rowerow-milanowek.html` (te same 4), `bleeding-hamulcow-shimano.html` (Offer + FAQPage), `centrowanie-i-zaplatanie-kol.html` (three wheel Offers + FAQPage), `serwis-rowerow-elektrycznych.html` (mechanical OfferCatalog + FAQPage; no electrical work), `llms-full.txt` (sekcje `## Pełna lista usług` i `## Cennik`) oraz `llms.txt` (krótkie podsumowanie usług/cen w intro). Notification text in `src/index.js` (SMS reminder/review templates, the seasonal email blast in `sendSeasonalReminders`) currently does **not** quote prices, but if you add a price to any of them, keep it in sync here too.
  - `BIKE_TYPES` — bike-type whitelist for the form (also duplicated as its own array in `umow.html`, alongside that page's copy of `SERVICES`; see the gotcha above).
  - `SCHEDULE` — opening-hours map keyed by day-of-week (0=Sun…6=Sat). Changes here change the available slots returned by `/api/availability`. ### `_headers` (cache-control for static assets)
`_headers` at the repo root is a Cloudflare assets-config file (consumed by the ASSETS binding, **not** served as a static asset, so it stays **out** of `.assetsignore`). It sets `/uploads/*` to `Cache-Control: public, max-age=31536000, immutable` so images/favicons/the hero poster cache for a year in the browser instead of revalidating every visit (without it the binding defaults to `max-age=0, must-revalidate`, i.e. a conditional request per asset on every repeat visit). HTML is deliberately left on the default so content edits go live immediately. It applies through the `env.ASSETS.fetch` passthrough even with `run_worker_first: true`. Filenames in `uploads/` are stable, so `immutable` is safe; if you ever overwrite an image in place rather than adding a new filename, bump the filename (or the cache will serve the old bytes for up to a year).

## Content conventions (load-bearing)

These come from explicit user preference, not house style — apply them to every text change:

1. **No em-dashes (—).** Use a comma, semicolon, colon, or rewrite. This includes JSON-LD answer strings, meta descriptions, visible copy, and any SMS/email text in `src/index.js`.
2. **Avoid "I-slope" narration.** No Polish sentences starting with "Ja" or leaning on first-person interjections as a stylistic device. Keep copy direct and second-person where possible.
3. **No suspension service (decision 2026-07-02).** The shop does NOT service suspension: never list "zawieszenie", "amortyzatory", damper/fork service, sag/kompresja/odbicie tuning, or suspension brands (RockShox, Fox, Manitou, DVO, X-Fusion) as an offered service anywhere (visible copy, JSON-LD, meta descriptions, llms files, SMS). "Full suspension" / "MTB z zawieszeniem" may appear only as a *bike type* the shop accepts (e.g. "Hardtail i full suspension. Hamulce, koła, napęd."), never as a serviced component.
4. **E-bike is mechanical only.** Offer brakes, drivetrain, wheels, and mechanical inspection. Never advertise diagnostics or repairs of batteries, controllers, wiring, motors, or motor electronics.

## Deploy / infra notes

- **Migrations before code, always.** On 2026-07-27 a `wrangler deploy` shipped a Worker that reads `request_rate_limits` (migration 0017) while production D1 was still on 0014; every public `POST` (`/api/bookings`, `/api/warsztaty`, `/api/reminders`) returned 500 `{"error":"Server error"}` for ~8 days, because `consumeRateLimit` runs before the route handlers and its `D1_ERROR` hits the top-level catch in `fetch`. Three guards now exist, all pointing at the same script: `scripts/deploy.sh` (= `npm run deploy`; applies migrations, deploys, smoke-tests) and a `PreToolUse` hook that denies a bare `wrangler deploy` while migrations are pending, wired for Claude Code in `.claude/settings.json` and for Codex in `.codex/hooks.json` (both call `scripts/pre-deploy-d1-check.sh`). Grok loads the Claude hook via compatibility (`matcher: Bash` also matches `run_terminal_command`); project hooks stay silent until the folder is trusted (`/hooks-trust`). To check a hook is alive, have the agent run `echo d1-hook-selftest`: a live hook blocks that command with a confirmation message. Codex additionally requires the user to accept its project-trust and hook-trust prompts once, in the interactive TUI, before project hooks run at all.
